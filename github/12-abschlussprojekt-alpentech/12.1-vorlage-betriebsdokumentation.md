## 4. Härtungsmaßnahmen

| Maßnahme | Server | Einstellung | Prüfbefehl |
|---|---|---|---|
| Zonentransfer begrenzt | beide | [Partneradresse] | `dig -b <fremde Adresse> @server zone AXFR` |
| Rekursion begrenzt | BIND | `allow-recursion { lab-nets; };` | `dig -b 192.168.60.100 @192.168.60.11 www.example.com` |
| Version verborgen | BIND | `version "unavailable";` | `dig @192.168.50.11 version.bind CHAOS TXT +short` |
| Rate Limiting | beide | [Windows: LogOnly; BIND: rate-limit] | [ ] |
| Cache Locking | Windows | 100 % | `Get-DnsServerCache` |

## 5. Betriebsabläufe

- **Eintrag ändern (dev):** Zonendatei bearbeiten, Seriennummer erhöhen, `sudo rndc reload dev.alpentech.internal`, Sekundär prüfen.
- **Eintrag ändern (hq):** Windows-DNS-Manager oder PowerShell; Windows erhöht die Seriennummer selbst.
- **Seriennummern vergleichen:** `bash 11.1-serial-vergleichen.sh <zone> 192.168.50.10 192.168.50.11`.
- **Abnahmetest wiederholen:** `bash 12.1-abnahme-pruefen.sh`.

## 6. Störungen: erste Schritte

| Symptom | Erste Prüfung |
|---|---|
| Zeitüberschreitung | Dienst läuft? Port 53 UDP und TCP offen? |
| `REFUSED` | ACL (`allow-query`, `allow-recursion`), Zone geladen? |
| `SERVFAIL` bei Sekundärzone | Primär erreichbar? Expire abgelaufen? `rndc zonestatus` |
| Alte Daten auf dem Sekundär | Seriennummer erhöht? NOTIFY/TCP 53 zum Primär? |
