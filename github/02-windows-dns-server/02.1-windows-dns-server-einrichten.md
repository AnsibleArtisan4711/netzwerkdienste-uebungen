## Lernziele

Nach dieser Übung kannst du

- die DNS-Server-Rolle per GUI und per PowerShell installieren und ihren Zustand prüfen,

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **dns.exe** | Prozess des Windows-DNS-Dienstes (Dienstname `DNS`). |
| **dnsmgmt.msc** | Verwaltungskonsole „DNS-Manager“. |
| **Modul `DnsServer`** | PowerShell-Cmdlets zur Verwaltung des DNS-Servers (`Get-DnsServer…`, `Set-DnsServer…`, `Add-DnsServer…`). Es kommt mit den Verwaltungswerkzeugen der Rolle. |
| **Lauschschnittstelle** | IP-Adresse, auf der der Server Anfragen annimmt. Standard: alle Adressen des Servers. |
| **Root Hints** | Liste der Wurzelserver, mit der ein rekursiver Server seine Auflösung beginnt. Windows speichert sie in der Datei `cache.dns` (und, wenn AD-integriert, im Active Directory). |
| **Rekursion** | Der Server löst unbekannte Namen stellvertretend für den Client auf. |
| **Dateibasierte Zone** | Zone, die in einer Textdatei unter `System32\dns` liegt (ab Modul 4). |

## Aufgabe

Jeder Schritt steht, wo es zwei Wege gibt, auf zwei Wegen: grafisch (GUI) und per PowerShell. PowerShell läuft **als Administrator** auf SRV-WIN-DNS, wenn nichts anderes steht.

### Teil 1: Die DNS-Rolle installieren

*(Lerneinheiten 2.1 und 2.2, Praxisaufgabe 1)*

**1. Rolle installieren**

- **GUI:** Server-Manager → *Verwalten* → *Rollen und Features hinzufügen* → *Rollenbasierte oder featurebasierte Installation* → Server auswählen → Serverrolle *DNS-Server* → die angebotenen Verwaltungstools mit hinzufügen → *Installieren*.
- **PowerShell:**

```powershell
Install-WindowsFeature -Name DNS -IncludeManagementTools
```

Oder mit Vorabprüfung und Zusammenfassung: `.\02.1-dns-rolle-installieren.ps1 -WhatIf`, dann ohne `-WhatIf`.

**2. Dienst prüfen**

```powershell
Get-Service DNS
Get-Service DNS | Select-Object Name, Status, StartType
```

Erwartet (*nicht bestätigt*): Status `Running`, Starttyp `Automatic`.

**3. Konsole öffnen**

- **GUI:** Server-Manager → *Tools* → *DNS*, oder `Win + R` → `dnsmgmt.msc`. Im Baum erscheinen der Server, *Forward-Lookupzonen*, *Reverse-Lookupzonen*, *Bedingte Weiterleitungen* und der Knoten *Globale Protokolle*. In dieser Übung gibt es noch keine Zonen.
- **PowerShell:** `Get-DnsServerZone` listet die Zonen. Bei einem frischen, nicht in einer Domäne befindlichen Server sind es nur die automatisch erstellten (z. B. `TrustAnchors`; *nicht bestätigt*).

**4. Verzeichnisstruktur und Registry ansehen**

```powershell
Get-ChildItem C:\Windows\System32\dns
Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Services\DNS\Parameters'
```

Notiere: Welche Dateien liegen im Verzeichnis (u. a. `cache.dns`)? Welche Werte stehen unter `Parameters`? Ändere hier **nichts** von Hand; Änderungen laufen über die Konsole oder die Cmdlets.

**5. DNS-Server für CLI-TEST-01 und SRV-WIN-DNS selbst eintragen**

- **GUI:** Adapter → *Eigenschaften* → *Internetprotokoll Version 4* → *Folgende DNS-Serveradressen verwenden* → `192.168.50.10`.
- **PowerShell** (Server **und** Client):

```powershell
Set-DnsClientServerAddress -InterfaceAlias 'Ethernet' -ServerAddresses 192.168.50.10
Get-DnsClientServerAddress -InterfaceAlias 'Ethernet' -AddressFamily IPv4
```

**6. Server von außen ansprechen**

Von CLI-TEST-01:

```powershell
Test-NetConnection 192.168.50.10 -Port 53
Resolve-DnsName -Name localhost -Server 192.168.50.10
```

Erwartet (*nicht bestätigt*): Die Rolleninstallation öffnet die Windows-Firewall für DNS (UDP und TCP, Port 53). `Test-NetConnection` meldet `TcpTestSucceeded : True`. Falls nicht: `Get-NetFirewallRule -DisplayGroup 'DNS*'` und die Regeln für Port 53 prüfen.

### Teil 2: Lauschschnittstellen und Root Hints

*(Lerneinheit 2.3, Praxisaufgabe 2)*

**1. Ausgangszustand lesen**

```powershell
(Get-DnsServerSetting -All).ListeningIPAddress
(Get-DnsServerSetting -All).AllIPAddress
```

`ListeningIPAddress` sind die Adressen, auf denen der Server tatsächlich lauscht; standardmäßig alle Adressen des Servers (`AllIPAddress`). Die Dokumentation zeigt für beide Eigenschaften eine Adressliste, z. B. `{172.23.90.136}`.

**2. Lauschadressen einschränken**

Ziel: nur `192.168.50.10`, `fd00:50::10` und die Loopback-Adresse.

- **GUI:** DNS-Manager → Rechtsklick auf den Server → *Eigenschaften* → Reiter *Schnittstellen* → *Nur folgende IP-Adressen* → die gewünschten Adressen markieren. Mit *OK* bestätigen; der Dienst startet dabei neu bzw. fragt danach.
- **PowerShell:** `Set-DnsServerSetting` hat **keinen** Parameter für Lauschadressen. Man liest das Einstellungsobjekt, ändert die Eigenschaft und schreibt es zurück:

```powershell
$s = Get-DnsServerSetting -All
$s.ListeningIPAddress = [System.Net.IPAddress[]]@('192.168.50.10', '127.0.0.1')
Set-DnsServerSetting -InputObject $s
Restart-Service DNS
```

  Mit Prüfung der Adressen und Neustart des Dienstes: `.\02.1-lauschadressen-setzen.ps1 -WhatIf`, dann ohne `-WhatIf`. Für IPv6 zusätzlich `-MitIPv6`.

> [!NOTE]
> Ob `ListeningIPAddress` IPv6-Adressen wie `fd00:50::10` zuverlässig annimmt, ist *nicht bestätigt*. Mit der GUI-Variante (Reiter *Schnittstellen*) klappt es sicher, soweit die Konsole die IPv6-Adresse anzeigt. Prüfe nach der Änderung beide Wege.

**3. Wirkung prüfen**

Von CLI-TEST-01:

```powershell
Resolve-DnsName -Name localhost -Server 192.168.50.10
```

Auf dem Server (`netstat` zeigt die lauschenden Adressen):

```powershell
netstat -ano -p UDP | Select-String ':53 '
```

Erwartet (*nicht bestätigt*): Port 53 erscheint nur noch mit `192.168.50.10`, `127.0.0.1` (und ggf. IPv6), nicht mehr mit `0.0.0.0`.

**4. Root Hints ansehen**

```powershell
Get-DnsServerRootHint
Get-Content C:\Windows\System32\dns\cache.dns | Select-Object -First 20
```

Die Datei beginnt mit Kommentaren und führt Einträge der Form `. <TTL> NS A.ROOT-SERVERS.NET.` sowie die zugehörigen Adressen (A und AAAA). Schreibe auf, wie viele Wurzelserver aufgeführt sind (A bis M) und welche Server IPv6-Adressen haben.

> [!NOTE]
> Nur wenn der Server **nicht** AD-integriert ist (hier der Fall bis Modul 8), kommt die Liste aus `cache.dns`. Microsoft weist darauf hin, dass ein Windows-DNS-Server mindestens einen Root Hint braucht und dass entfernte Root Hints wieder erscheinen können, wenn sie noch in `cache.dns` oder im Active Directory stehen (siehe Quellen). **Entferne in dieser Übung keine Root Hints.**

### Teil 3: Erste Verwaltung mit PowerShell und Ereignislog

*(Lerneinheit 2.4)*

**1. Überblick holen**


`Get-DnsServer` liefert das gesamte Konfigurationsobjekt des Servers (Einstellungen, Rekursion, Zonen u. a.), `Get-DnsServerSetting -All` die vollständigen Servereinstellungen. Die Dokumentation zeigt für `Get-DnsServerSetting -All` u. a. die Eigenschaften `EnableDnsSec`, `EnableIPv6`, `RoundRobin`, `LocalNetPriority`, `MaximumUdpPacketSize` und `ListeningIPAddress`.

**2. Einstellungen sichern**

```powershell

```

Das Skript schreibt sechs Textdateien nach `C:\Uebung\dns-sicherung` (Einstellungen, Rekursion, Root Hints, Weiterleitungen, Cache, Zonen) mit Zeitstempel im Namen. Es verändert nichts am Server. Öffne eine Datei und finde `ListeningIPAddress`.

**3. Dienst steuern**

```powershell
Stop-Service DNS
Resolve-DnsName -Name localhost -Server 192.168.50.10 -ErrorAction SilentlyContinue
Start-Service DNS
Get-Service DNS
```

Notiere, was der Client beim ausgeschalteten Dienst sieht (*Zeitüberschreitung bzw. Fehler*, *nicht bestätigt*).

**4. Ereignislog lesen**

- **GUI:** DNS-Manager → *Globale Protokolle* → *DNS-Ereignisse*, oder Ereignisanzeige → *Anwendungs- und Dienstprotokolle* → *DNS-Server*.
- **PowerShell:**

```powershell

```

Finde die Einträge, die zu deinem `Stop-Service` und `Start-Service` gehören. Die Ereignis-Nummern kannst du dir für die Fehlersuche (Modul 11) notieren; der Lehrplan verlangt keine bestimmten Nummern.

### Teil 4: Rekursion im isolierten Labor

*(Lerneinheit 2.3, Praxisaufgabe 3)*

Der Server hat Root Hints, aber im Labor keine Verbindung zu den Wurzelservern. Was passiert bei einer Abfrage für einen Namen, den der Server nicht selbst verwaltet?

**1. Mit Rekursion abfragen und die Zeit messen** (CLI-TEST-01)

```powershell
Measure-Command { Resolve-DnsName -Name example.net -Server 192.168.50.10 -ErrorAction SilentlyContinue } | Select-Object TotalSeconds
```

Erwartet (*nicht bestätigt*): Es kommt **keine Adresse**. Je nach Netzanbindung dauert die Antwort Sekunden (Zeitüberschreitung, der Server probiert Wurzelserver), oder sie kommt sofort mit einem Fehler (SERVFAIL), wenn das Betriebssystem sofort „Netz nicht erreichbar“ meldet, weil es kein Gateway gibt. Eine Messung mit BIND auf einem Rechner ganz ohne Netz lieferte sofort SERVFAIL (`beispiele/04-servfail-extern.txt` in Modul 01). Notiere deinen Wert; er ist Teil der Aufgabe.

**2. Rekursion ausschalten und wiederholen** (Server)

```powershell
Set-DnsServerRecursion -Enable $false -PassThru
```

Die Dokumentation zeigt als Ausgabe von `Set-DnsServerRecursion … -PassThru` eine Tabelle mit `Enable`, `AdditionalTimeout(s)`, `RetryInterval(s)`, `Timeout(s)` und `SecureResponse`. Wiederhole die Abfrage von CLI-TEST-01. Erwartet (*nicht bestätigt*): sofortige Antwort mit einem Fehler statt Wartezeit.

- **GUI-Weg zum selben Ergebnis:** DNS-Manager → Server → *Eigenschaften* → Reiter *Erweitert* → Haken bei *Rekursion deaktivieren* (Bezeichnung *nicht bestätigt*; in der englischen Oberfläche *Disable recursion (also disables forwarders)*).

**3. Wiederherstellen (Pflicht)**

Modul 07 braucht Rekursion für Weiterleitungen. Schalte sie am Ende **wieder ein** und prüfe:

```powershell
Set-DnsServerRecursion -Enable $true -PassThru
(Get-DnsServerRecursion).Enable
```

Erwartet: `True`.

## Hintergrund

### Aufbau des Windows-DNS-Dienstes

Der DNS-Server ist ein Systemdienst (`dns.exe`, Dienstname `DNS`) und kommt als Serverrolle. Verwaltet wird er mit der Konsole `dnsmgmt.msc`, mit dem PowerShell-Modul `DnsServer` oder mit dem älteren `dnscmd`. Die Konfiguration liegt in der Registry (`HKLM\SYSTEM\CurrentControlSet\Services\DNS`); dateibasierte Zonen liegen als Textdateien unter `%SystemRoot%\System32\dns`; sind Zonen AD-integriert, liegen sie im Verzeichnisdienst.

### Warum die Lauschschnittstellen?

Ein Server mit mehreren Netzwerkkarten soll DNS oft nur auf einer Adresse anbieten (z. B. nicht nach außen). Der Standard „alle Adressen“ ist bequem, aber großzügig. Vorsicht: Wird nur die Serveradresse eingetragen, kann der Server bei manchen Konstellationen sich selbst nicht mehr über Loopback befragen. Deshalb gehört `127.0.0.1` in dieser Übung dazu.

### Root Hints

Ein rekursiver Server braucht einen Einstiegspunkt: Die Root Hints nennen die Wurzelserver. Im isolierten Labor führen sie ins Leere, was erst nach Wartezeit auffällt. Wer wirklich nur eigene Zonen bedienen will, schaltet Rekursion ab oder beschränkt sie; in Modul 07 kommen Weiterleitungen dazu, die die Root Hints ersetzen.

## Hinweise

- Änderungen mit `Set-DnsServerSetting` wirken teils erst nach einem Neustart des Dienstes. Die Skripte starten ihn selbst.
- Wenn die GUI und PowerShell unterschiedliche Lauschadressen zeigen, den Dienst neu starten und `Get-DnsServerSetting -All` erneut abrufen.
- Alle Befehle mit `-ComputerName` lassen sich auch von einem anderen Rechner aus nutzen. In dieser Übung arbeitest du lokal.
- Keine Snapshots der laufenden Windows-VMs zurücksetzen, ohne danach die Zeit zu prüfen.

### Antworten auf die Kontrollfragen

1. `%SystemRoot%\System32\dns` (üblich `C:\Windows\System32\dns`).
2. Der Server versucht, die Wurzelserver aus den Root Hints zu erreichen. Im Labor gibt es keinen Weg dorthin. Je nach Netzkonfiguration scheitert der Versuch sofort (kein Weg) oder erst nach Zeitüberschreitung; beides ergibt keine Adresse beim Client. Die Wartezeit ist die Summe der Versuche und Wiederholungen.
3. `Get-DnsServer` (gesamtes Konfigurationsobjekt) bzw. `Get-DnsServerSetting -All` (Servereinstellungen).
4. Die Lauschadressen sind eine Eigenschaft des Einstellungsobjekts. `Set-DnsServerSetting` übernimmt nur ein Objekt über `-InputObject`: Objekt lesen (`Get-DnsServerSetting -All`), Eigenschaft `ListeningIPAddress` ändern, Objekt zurückschreiben.
5. Weiterleitungen und die Auflösung externer Namen setzen Rekursion voraus (Modul 07). Bleibt sie aus, scheitern die späteren Tests aus einem Grund, der nichts mit den neuen Einstellungen zu tun hat.
