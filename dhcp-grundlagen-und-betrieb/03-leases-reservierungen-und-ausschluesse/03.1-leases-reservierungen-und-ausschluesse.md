## Lernziele

Nach dieser Übung kannst du

- die Lease-Dauer für Büro, Gäste und serverähnliche Geräte begründet wählen und die Erneuerung im Mitschnitt nachweisen,
- eine Reservierung einrichten und von einer statischen Adresse am Gerät abgrenzen,
- Ausschlussbereiche anlegen, die Konflikterkennung des Servers aktivieren und einen Adresskonflikt auswerten,
- die Auslastung eines Scopes auslesen und berechnen.

## Voraussetzungen

- Modul 2 abgeschlossen, Checkpoint `M3-Anfang` auf `SRV-WIN-DHCP1` (Teil 1).
- `CLI-WIN-A` hängt an `vSwitch-Server`, holt per DHCP eine Adresse.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **Reservierung** | Feste Zuordnung einer Adresse zu einer MAC-Adresse (Client-Identifier) im Scope. |
| **Ausschlussbereich** | Adressen innerhalb des Scope-Bereichs, die der Server **nicht** vergibt. |
| **Konflikterkennung** | Der Server prüft vor der Vergabe, ob die Adresse schon antwortet (`ConflictDetectionAttempts`, 0 bis 5 Versuche). |
| **Auslastung** | Anteil vergebener Adressen an allen vergebbaren. |
| **Statische Adresse am Gerät** | Adresse, die am Client selbst eingetragen ist; der Server weiß davon nichts. |

## Aufgabe

### Teil 1: Lease-Dauer und Erneuerung im Mitschnitt

*(Lerneinheit 3.1, Praxisaufgabe 1)*

**1. Checkpoint**

```powershell
Checkpoint-VM -Name SRV-WIN-DHCP1 -SnapshotName M3-Anfang    # Hyper-V-Host
```

**2. Lease-Dauer des Scopes auf 30 Minuten setzen**

- **GUI:** `dhcpmgmt.msc` → Scope `Netz-A` → *Eigenschaften* → Lease-Dauer 0 Tage, 0 Stunden, 30 Minuten.
- **PowerShell:**

```powershell
Set-DhcpServerv4Scope -ScopeId 192.168.10.0 -LeaseDuration (New-TimeSpan -Minutes 30)
(Get-DhcpServerv4Scope -ScopeId 192.168.10.0).LeaseDuration
```

**3. Mitschnitt starten und Lease holen**

Auf `RTR-LIN`: `sudo ./01.1-mitschnitt.sh net-a`. Auf `CLI-WIN-A`: `ipconfig /release`, `ipconfig /renew`, `ipconfig /all` (Beginn und Ablauf notieren).

**4. Erneuerung abwarten**

Nach etwa 15 Minuten (T1 = 50 %) sollte im Mitschnitt eine REQUEST-Nachricht des Clients erscheinen, die sich an die Adresse des Servers richtet, nicht an den Broadcast. Notiere Zeitpunkt und Zieladresse. Erwartet (*nicht bestätigt*): Windows beginnt die Erneuerung nach etwa der Hälfte der Lease-Dauer. Die Wartezeit nutzt du für Teil 2, du musst den Mitschnitt aber im Blick behalten.

**5. Rückbau**

```powershell
Set-DhcpServerv4Scope -ScopeId 192.168.10.0 -LeaseDuration (New-TimeSpan -Hours 8)
```

Erneuere danach den Lease auf `CLI-WIN-A`.

### Teil 2: Reservierung

*(Lerneinheit 3.2, Praxisaufgabe 2)*

**1. MAC-Adresse von `CLI-WIN-A` ermitteln** (`CLI-WIN-A`)

```powershell
Get-NetAdapter | Select-Object Name, MacAddress
```

Die Schreibweise in der Ausgabe ist `00-15-5D-xx-xx-xx`. Auf dem Hyper-V-Host: `Get-VMNetworkAdapter -VMName CLI-WIN-A | Select-Object MacAddress` (ohne Trennzeichen).

**2. Reservierung anlegen**

- **GUI:** `dhcpmgmt.msc` → Scope → *Reservierungen* → *Neue Reservierung*: Name, IP `192.168.10.150`, MAC-Adresse, unterstützter Typ *Beides*.
- **PowerShell:**

```powershell
Add-DhcpServerv4Reservation -ScopeId 192.168.10.0 -IPAddress 192.168.10.150 `
    -ClientId '00-15-5D-xx-xx-xx' -Name 'CLI-WIN-A' -Description 'Reservierung Modul 3'
Get-DhcpServerv4Reservation -ScopeId 192.168.10.0
```

Oder mit `.\03.1-reservierung-anlegen.ps1 -ClientId 00-15-5D-xx-xx-xx -WhatIf`, dann ohne `-WhatIf`. Setze deine eigene MAC-Adresse ein. Die Adresse `.150` liegt innerhalb des Pools `.100–.199`. Ob Windows Reservierungen außerhalb des Scope-Bereichs zulässt, ist *nicht bestätigt* und wird hier nicht verwendet; die Lerneinheit 3.2 nennt den Vergleich innerhalb und außerhalb des Bereichs, prüfe ihn bei Interesse als Erweiterung.

**3. Erneuern und prüfen**

```powershell
ipconfig /release
ipconfig /renew
ipconfig /all
```

Erwartet: `CLI-WIN-A` hat `192.168.10.150`, Optionen unverändert (Router, DNS, Domäne). Prüfe auf dem Server:

```powershell
Get-DhcpServerv4Lease -ScopeId 192.168.10.0
```

Die Reservierung bleibt für Modul 4 bestehen.

### Teil 3: Adresskonflikt erzeugen und auswerten

*(Lerneinheit 3.3, Praxisaufgabe 3)*

**1. Konflikterkennung aktivieren**

```powershell
Get-DhcpServerSetting
Set-DhcpServerSetting -ConflictDetectionAttempts 1
(Get-DhcpServerSetting).ConflictDetectionAttempts
```

Der Wert ist die Zahl der Prüfversuche vor der Vergabe (0 bis 5, Standard 0). Notiere den Ausgangswert. Das Cmdlet liest und setzt nur diese Einstellung; ein Neustart des Dienstes ist laut Dokumentation nicht erwähnt (*nicht bestätigt*).

**2. Ausgangslage herstellen**

```powershell
Remove-DhcpServerv4Reservation -ScopeId 192.168.10.0 -IPAddress 192.168.10.150
```

Auf `CLI-WIN-A`: `ipconfig /release`.

**3. Konflikt erzeugen** (`RTR-LIN`)

```bash
sudo ip addr add 192.168.10.100/24 dev net-a
ip -br addr show net-a
```

`.100` ist die erste Adresse des Pools. `RTR-LIN` beantwortet damit Anfragen (z. B. Ping), obwohl der DHCP-Server die Adresse für frei hält.

**4. Neue Lease anfordern und beobachten** (`CLI-WIN-A`)

```powershell
ipconfig /renew
ipconfig /all
```

Wird `.100` übersprungen? Erwartet (*nicht bestätigt*): Der Server prüft die Adresse vor der Vergabe und bietet `192.168.10.101` an. Prüfe die Lease-Tabelle (`Get-DhcpServerv4Lease`); die Ereignisprotokolle behandelt Modul 10. Alternativ erkennt der Client den Konflikt selbst (RFC 5227) und sendet DECLINE; auch das ist im Mitschnitt zu sehen.

**5. Rückbau (Pflicht)**

```bash
sudo ip addr del 192.168.10.100/24 dev net-a
```

```powershell
Set-DhcpServerSetting -ConflictDetectionAttempts 0   # Ausgangswert, den du notiert hast
Add-DhcpServerv4Reservation -ScopeId 192.168.10.0 -IPAddress 192.168.10.150 `
    -ClientId '00-15-5D-xx-xx-xx' -Name 'CLI-WIN-A'
```

Erneuere den Lease auf `CLI-WIN-A` und prüfe, dass wieder `.150` vergeben wird.

### Teil 4: Ausschluss und Auslastung

*(Lerneinheit 3.4, Praxisaufgabe 4)*

**1. Ausschlussbereich anlegen**

- **GUI:** Scope → *Adresspool* → Rechtsklick → *Neuer Ausschlussbereich*: `192.168.10.190` bis `192.168.10.199`.
- **PowerShell:**

```powershell
Add-DhcpServerv4ExclusionRange -ScopeId 192.168.10.0 -StartRange 192.168.10.190 -EndRange 192.168.10.199
Get-DhcpServerv4ExclusionRange -ScopeId 192.168.10.0
```

Der Bereich bleibt in allen folgenden Modulen bestehen.

**2. Statistik lesen**

```powershell
Get-DhcpServerv4ScopeStatistics -ScopeId 192.168.10.0 | Format-List *
```

Notiere, welche Eigenschaften es gibt (z. B. freie, vergebene, reservierte Adressen). Die Namen sind *nicht bestätigt*; `Get-Member` zeigt sie.

**3. Auslastung berechnen**

```powershell
$s = Get-DhcpServerv4ScopeStatistics -ScopeId 192.168.10.0
[math]::Round(100 * $s.InUse / ($s.InUse + $s.Free), 1)
```

Oder `.\03.1-auslastung-anzeigen.ps1`. Vergleiche mit dem Wert in `dhcpmgmt.msc` (Scope → *Statistik* bzw. Spalte *Verwendung*). Beachte: Verwendet der Server `Reserved` und `Pending` anders in der Berechnung, weicht dein Ergebnis ab (*nicht bestätigt*); notiere die Differenz.

**4. Prüfen, dass die Ausschlüsse greifen**

Die Zahl der verfügbaren Adressen sinkt um 10. Fordere mit `CLI-WIN-A` einen Lease an; er darf nicht aus `.190–.199` stammen.

## Hintergrund

### Wahl der Lease-Dauer

Kurze Leases geben Adressen schnell zurück (Gäste, Besucher-WLAN), erzeugen aber viel Verkehr und Last. Lange Leases schonen den Server, halten aber Adressen von abgeschalteten Geräten fest und verzögern Änderungen (neues Gateway, neuer DNS-Server). Für Büro-Clients sind Stunden bis Tage üblich, für Gäste Minuten bis Stunden. Wie lange Clients nach einem Serverausfall noch laufen, bestimmt die Hälfte (T1) und T2.

### Reservierung oder statische Adresse?

Eine statische Adresse am Gerät ist unabhängig vom Server, aber unsichtbar im DHCP: Der Server kann sie vergeben (Konflikt) und die Dokumentation fehlt. Eine Reservierung hält Adresse und Optionen zentral, ändert sich beim Wechsel des DNS-Servers automatisch und ist in der Lease-Tabelle sichtbar. Geräte, die unabhängig von DHCP funktionieren müssen (Router, DHCP-Server selbst), erhalten trotzdem statische Adressen außerhalb des Pools.

### Konflikterkennung

Der Server prüft vor der Vergabe, ob die Adresse schon antwortet (vermutlich per ICMP-Ping, *nicht bestätigt*). Der Client prüft nach dem Empfang per ARP (RFC 5227) und lehnt mit DECLINE ab. Beide Wege sind unvollkommen: Geräte, die nicht auf Ping antworten (Firewall), bleiben unentdeckt.

## Hinweise

- Mit `-WhatIf` an den Skripten siehst du, was passiert. Das Entfernen der Reservierung in Teil 3 ist Absicht: Mit Reservierung auf `.150` würde der Konflikttest nicht ausgelöst.
- Konflikterkennung verzögert jede Vergabe um die Prüfzeit. Im Betrieb meist 0 oder 1.
- Vergiss den Rückbau von Teil 3 nicht: eine Zusatzadresse auf `RTR-LIN` stört später das Relay.

### Antworten auf die Kontrollfragen

1. Kurze Leases erzeugen ständig Erneuerungsverkehr, belasten den Server und machen Clients empfindlicher gegen Serverausfälle (Erneuerung scheitert früh). Sinnvoll sind sie bei Gästen oder knappem Adresspool.
2. Die Reservierung ist im Server hinterlegt: zentral sichtbar, Optionen ändern sich mit, Adresse ist vor Vergabe an andere geschützt. Eine statische Adresse am Gerät kennt der Server nicht (Konfliktgefahr, Lücke in der Dokumentation).
3. Der Client sendet nach dem Erhalt per ARP eine Anfrage nach der Adresse (ARP-Probe). Antwortet jemand, lehnt er die Adresse mit **DHCPDECLINE** ab.
4. Auslastung = vergebene Adressen ÷ (vergebene + freie Adressen) × 100. Ausgeschlossene Adressen zählen nicht zur Grundmenge. Wie der Server Reservierungen zählt, ist *nicht bestätigt*.
