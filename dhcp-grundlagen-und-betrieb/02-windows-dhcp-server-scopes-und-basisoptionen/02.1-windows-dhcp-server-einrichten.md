## Lernziele

Nach dieser Übung kannst du

- die DHCP-Server-Rolle per GUI und PowerShell installieren, die Sicherheitsgruppen anlegen und die Netzwerkbindung prüfen,
- einen IPv4-Scope mit Bereich, Maske, Lease-Dauer und Aktivierung planen und anlegen,
- Server- und Scope-Optionen (Router, DNS-Server, Domänenname) setzen und deren Vorrang erklären,
- einen DORA-Austausch im Mitschnitt mit der Lease-Tabelle des Servers vergleichen.

## Voraussetzungen

- Labor aus Modul 1: `RTR-LIN` mit `192.168.10.1` in Netz A, `CLI-WIN-A` an `vSwitch-Server`, DHCP-Client.
- `SRV-WIN-DHCP1`: Windows Server 2022/2025 mit Desktop (2 vCPUs, 4 GB RAM, 60 GB), 1 Adapter an `vSwitch-Server`, Arbeitsgruppe.
- Checkpoint `M2-Anfang` auf `SRV-WIN-DHCP1` (siehe Teil 1).

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **Dienst `DHCPServer`** | Systemdienst des Windows-DHCP-Servers. |
| **`dhcpmgmt.msc`** | Verwaltungskonsole „DHCP“. |
| **Modul `DhcpServer`** | PowerShell-Cmdlets (`Get-DhcpServerv4…`, `Add-DhcpServerv4…`, `Set-DhcpServerv4…`). |
| **Scope** | Adressbereich eines Subnetzes samt Lease-Dauer und Optionen; erst ein *aktiver* Scope vergibt. |
| **Serveroption / Scope-Option** | Optionswert für alle Scopes bzw. nur für einen Scope; der Scope-Wert gilt vor dem Serverwert. |
| **`DHCP Administrators`, `DHCP Users`** | Lokale Sicherheitsgruppen für Verwaltung und Leserechte. |

## Aufgabe

### Teil 1: Server vorbereiten und Rolle installieren

*(Lerneinheiten 2.1 und 2.2, Praxisaufgabe 1)*

**1. Checkpoint und feste Adresse** (Hyper-V-Host bzw. `SRV-WIN-DHCP1`)

```powershell
Checkpoint-VM -Name SRV-WIN-DHCP1 -SnapshotName M2-Anfang          # Host
```

```powershell
New-NetIPAddress -InterfaceAlias 'Ethernet' -IPAddress 192.168.10.11 -PrefixLength 24 -DefaultGateway 192.168.10.1
Set-DnsClientServerAddress -InterfaceAlias 'Ethernet' -ServerAddresses 192.168.10.10
Get-NetIPAddress -InterfaceAlias 'Ethernet' -AddressFamily IPv4
```

Der Adaptername kann abweichen (`Get-NetAdapter`). Wende `New-NetIPAddress` nur an, wenn die Adresse noch nicht gesetzt ist.

**2. Rolle installieren**

- **GUI:** Server-Manager → *Verwalten* → *Rollen und Features hinzufügen* → Serverrolle *DHCP-Server* → Verwaltungstools mit installieren.
- **PowerShell:**

```powershell
Install-WindowsFeature -Name DHCP -IncludeManagementTools
```

Oder mit Vorabprüfung: `.\02.1-dhcp-rolle-installieren.ps1 -WhatIf`, dann ohne `-WhatIf`. Die Windows-Rollen kommen aus dem lokalen Komponentenspeicher; ob dafür eine Internetverbindung nötig ist, ist *nicht bestätigt*.

**3. Sicherheitsgruppen anlegen und Dienst neu starten**

```powershell
netsh dhcp add securitygroups
Restart-Service DHCPServer
Get-Service DHCPServer
```

Der Befehl legt die lokalen Gruppen `DHCP Administrators` und `DHCP Users` an. Erwartet: Status `Running`. Prüfe die Gruppen mit `Get-LocalGroup | Where-Object Name -like 'DHCP*'`.

**4. Bindung prüfen**

```powershell
Get-DhcpServerv4Binding
```

Erwartet (*nicht bestätigt*): ein Eintrag für den Adapter mit `192.168.10.11` und `BindingState = True`. Der Server vergibt nur auf gebundenen Schnittstellen.

**5. Verzeichnisse ansehen**

```powershell
Get-ChildItem "$env:SystemRoot\System32\dhcp"
Get-DhcpServerDatabase
```

Notiere den Datenbank- und Sicherungspfad aus `Get-DhcpServerDatabase`. Standard `%SystemRoot%\System32\dhcp` ist *nicht bestätigt*.

**6. Beobachtung: Server in Arbeitsgruppe**

Der Server ist noch kein Domänenmitglied und deshalb nicht in Active Directory autorisierbar. Ob er dennoch Adressen vergibt, ist *nicht bestätigt*; du hältst das Ergebnis in Teil 3 fest.

### Teil 2: Scope für Netz A

*(Lerneinheiten 2.3 und 2.4, Praxisaufgabe 2)*

Plane den Scope `Netz-A` auf Papier, bevor du ihn anlegst:

| Eigenschaft | Wert |
|---|---|
| Name | `Netz-A` |
| Netz | `192.168.10.0/24` |
| Bereich | `192.168.10.100` bis `192.168.10.199` |
| Maske | `255.255.255.0` |
| Lease-Dauer | 8 Stunden |
| Router (Option 3) | `192.168.10.1` |
| DNS-Server (Option 6) | `192.168.10.10` |
| DNS-Domänenname (Option 15) | `corp.example.com` |

**Scope anlegen und aktivieren**

- **GUI:** `dhcpmgmt.msc` → Server → *IPv4* → Rechtsklick → *Neuer Bereich* → Assistent: Name, Adressbereich, Maske, Ausschlüsse (keine), Lease-Dauer 8 Stunden, Optionen jetzt konfigurieren: Router, Domäne und DNS, WINS (leer), Bereich jetzt aktivieren.
- **PowerShell:**

```powershell
Add-DhcpServerv4Scope -Name 'Netz-A' -StartRange 192.168.10.100 -EndRange 192.168.10.199 `
    -SubnetMask 255.255.255.0 -LeaseDuration (New-TimeSpan -Hours 8) -State Active
Set-DhcpServerv4OptionValue -ScopeId 192.168.10.0 -Router 192.168.10.1 `
    -DnsServer 192.168.10.10 -DnsDomain corp.example.com
Get-DhcpServerv4Scope
Get-DhcpServerv4OptionValue -ScopeId 192.168.10.0
```

Oder `.\02.1-scope-netz-a-anlegen.ps1 -WhatIf`, dann ohne `-WhatIf`. Der Parameter `-State` akzeptiert `Active` und `InActive`; den Standardwert habe ich nicht geprüft (*nicht bestätigt*). Deshalb steht `-State Active` immer dabei. Achte bei `Set-DhcpServerv4OptionValue` auf `-ScopeId`: Ohne diesen Parameter wirkt der Wert auf Serverebene, nicht auf den Scope.

Erwartet: ein Scope `Netz-A`, Status `Active`, Lease-Dauer `08:00:00`; drei Optionswerte (3, 6, 15).

> [!NOTE]
> Beim Anlegen des Scopes kann die Warnung erscheinen, dass der DHCP-Server nicht in Active Directory autorisiert ist. Das gehört zu Teil 1, Schritt 6. Die Autorisierung wird in Modul 6 nachgeholt.

### Teil 3: Der erste Lease mit Mitschnitt

*(Lerneinheit 2.5, Praxisaufgabe 3)*

**1. Mitschnitt starten** (`RTR-LIN`)

```bash
sudo ./01.1-mitschnitt.sh net-a
```

**2. Lease anfordern** (`CLI-WIN-A`)

```powershell
ipconfig /release
ipconfig /renew
ipconfig /all
```

**3. Auswerten**

- Finde im Mitschnitt die vier DORA-Nachrichten und notiere für jede: Quell- und Ziel-IP, `xid`, Nachrichtentyp, angebotene Adresse. Die Reihenfolge und das Aussehen der Felder siehe [`beispiele/02-dora-mitschnitt.md`](beispiele/02-dora-mitschnitt.md) (Linux-Testlauf mit Kea als Server; ein Windows-Server sendet dieselben Nachrichten, die Optionen und ihre Reihenfolge können abweichen, *nicht bestätigt*).
- Vergleiche die Adresse und die Optionen aus dem OFFER/ACK mit `ipconfig /all`: Standardgateway, DNS-Server, DNS-Suffix, Lease-Beginn und -Ablauf.
- Vergleiche mit der Lease-Tabelle des Servers:

```powershell
Get-DhcpServerv4Lease -ScopeId 192.168.10.0
```

Erwartet (sinngemäß): ein Eintrag mit `IPAddress 192.168.10.100`, der MAC-Adresse (`ClientId`) von `CLI-WIN-A`, Hostname und Ablaufzeit (`LeaseExpiryTime`). Frage dich: Was steht in der Tabelle, das im Mitschnitt nicht zu sehen ist (Hostname-Ablauf, Zustand der Lease)?

**4. Notiere**: Hat der Server in Teil 1, Schritt 6 bereits vergeben, obwohl er nicht autorisiert war? Halte das Ergebnis mit Datum fest (*nicht bestätigt*).

### Teil 4: Vorrang von Optionen

*(Lerneinheit 2.4, Praxisaufgabe 4)*

**1. Falschen Serverwert setzen**

```powershell
Set-DhcpServerv4OptionValue -DnsServer 192.168.10.99
Get-DhcpServerv4OptionValue                       # Serverebene
Get-DhcpServerv4OptionValue -ScopeId 192.168.10.0 # Scope-Ebene
```

**2. Lease erneuern und Wert prüfen** (`CLI-WIN-A`)

```powershell
ipconfig /renew
ipconfig /all | Select-String 'DNS'
```

Welcher Wert steht beim Client: `192.168.10.99` oder `192.168.10.10`? Erwartet: `192.168.10.10`, weil die Scope-Ebene vor der Serverebene gilt.

**3. Serverwert entfernen**

```powershell
Remove-DhcpServerv4OptionValue -OptionId 6
Get-DhcpServerv4OptionValue
```

Bestätige, dass auf Serverebene kein Wert 6 mehr steht und auf dem Client weiterhin `192.168.10.10` gilt. Hinweis: Das Cmdlet entfernt ohne `-ScopeId` die Option auf Serverebene; prüfe vor dem Aufruf, dass du die Scope-Ebene nicht erwischst.

## Hintergrund

### Aufbau

Der DHCP-Server ist ein Systemdienst (`DHCPServer`). Die Konfiguration liegt in einer Datenbank, Sicherungen und Protokolle liegen im Verzeichnis des Dienstes. Verwaltet wird mit der Konsole, dem Modul `DhcpServer` oder `netsh dhcp`.

### Scope und Aktivierung

Ein Scope beschreibt ein Subnetz. Ein angelegter, aber *nicht aktivierter* Scope ist Konfiguration ohne Wirkung: Der Server antwortet nicht aus ihm. Pools sollten kleiner als das Subnetz sein; die Adressen davor und danach bleiben für Router, Server und Reservierungen.

### Optionsebenen

Server-Optionen gelten für alle Scopes, Scope-Optionen nur für einen. Bei Widerspruch gewinnt die speziellere Ebene (Scope vor Server). Reservierungen und Policies kommen in den Modulen 3 und 4 dazu.

## Hinweise

- Ändere keine Werte in der Datenbankdatei von Hand; nutze Konsole oder Cmdlets.
- `ipconfig /release` und `/renew` können im Windows-Client Wartezeit erzeugen, wenn der Server nicht antwortet. Prüfe zuerst den Dienst und den Scope-Status.
- Jede Änderung am Server, die später zurückgebaut wird, steht mit **Rückbau** in der Aufgabe. Hier: Teil 4, Schritt 3.
