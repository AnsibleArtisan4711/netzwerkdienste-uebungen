Das Skript zur Kea-Sicherung lief real (Ubuntu 24.04); alle Windows-Skripte wurden nur auf Syntax geprüft. *Nicht bestätigt*: `Backup-DhcpServer`/`Restore-DhcpServer`, Namensmuster der Audit-Logdateien, Name des Ereignisprotokolls, Eigenschaftsnamen `InUse`/`Free` der Statistik.

## Lernziele

Nach dieser Übung kannst du

- Auslastung, Ereignisse und Audit-Log eines DHCP-Servers auswerten,
- Schwellenwerte für Warnungen festlegen und automatisiert prüfen,
- Konfiguration und Leases sichern (Windows und Kea) und eine Wiederherstellung durchführen,
- einen DHCP-Server auf einen anderen migrieren,
- eine Betriebsdokumentation mit Adressplan, Optionen und Wiederherstellungsablauf erstellen.

## Voraussetzungen

- Windows-Server aus Modul 2 bis 5 mit mindestens zwei Scopes und einigen Leases, optional `SRV-WIN-DHCP2` als zweiter Server (frisch, nur Rolle, ohne Scopes, Failover aus Modul 7 aufgelöst).
- `SRV-LIN-KEA` aus Modul 8.
- Checkpoint `M10-Anfang` auf `SRV-WIN-DHCP1`.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **Scope-Statistik** | Kennzahlen eines Scopes: belegte und freie Adressen, Prozentwert. |
| **Audit-Log** | Textdatei, in die der Windows-DHCP-Dienst Vergaben, Erneuerungen und Ereignisse schreibt. |
| **Export / Import** | Sicherung der Konfiguration (und optional der Leases) in eine XML-Datei und Rückspielen. |
| **Migration** | Übernahme der Konfiguration eines Servers auf einen anderen. |
| **RTO / RPO** | Wie lange darf die Wiederherstellung dauern, wie viele Daten dürfen verloren gehen. |

## Aufgabe

### Teil 1: Überwachung der Auslastung

*(Lerneinheit 10.1, Praxisaufgabe 1)*

1. Statistik ansehen:

```powershell
Get-DhcpServerv4ScopeStatistics | Select-Object ScopeId, PercentageInUse
```

Ob die Ausgabe auch `InUse` und `Free` enthält, ist *nicht bestätigt*; notiere die tatsächlichen Spaltennamen (`Get-DhcpServerv4ScopeStatistics | Format-List *`).

2. Warnschwelle prüfen: `.\10.1-auslastung-pruefen.ps1 -SchwellePro 80`. Das Skript meldet Scopes über der Schwelle und kann mit `-Protokoll C:\DhcpSicherung\auslastung.log` eine Zeile anhängen.
3. Auslastung provozieren: Verkleinere im Labor den Pool von `Netz-B` auf wenige Adressen (zum Beispiel `192.168.20.100–192.168.20.104`) und fordere von mehreren Clients Adressen an, bis der Wert über der Schwelle liegt. Hinweis zum Zurückstellen: siehe Aufräumen.
4. Linux: Zählen der Leases in der Kea-CSV-Datei:

```bash
sudo awk -F, -v jetzt="$(date +%s)" 'NR>1 {l[$1]=$4" "$5" "$10} END {for (a in l) {split(l[a],f," "); if (f[1]>0 && f[2]>jetzt && f[3]==0) n++}; print n+0}' /var/lib/kea/kea-leases4.csv
```

Das Kommando nimmt je Adresse die **letzte** Zeile (die Datei wird angehängt) und zählt sie, wenn `valid_lifetime` größer 0 ist (freigegebene Leases stehen mit 0 in der Datei), die Ablaufzeit (`expire`, Unix-Zeit) in der Zukunft liegt und `state` gleich 0 ist. Im Testlauf mit einer freigegebenen und einer reservierten Lease ergab es `1`. Die Spalten stehen in der Kopfzeile (`address,hwaddr,client_id,valid_lifetime,expire,subnet_id,fqdn_fwd,fqdn_rev,hostname,state,…`).

### Teil 2: Ereignisse und Audit-Log

*(Lerneinheit 10.2, Praxisaufgabe 2)*

1. Einstellungen des Audit-Logs: `Get-DhcpServerAuditLog` (Pfad, Aktivierung). Dort steht **nicht**, was passiert ist.
2. Inhalt lesen: `.\10.1-audit-log-lesen.ps1 -Zeilen 40`. Das Skript nimmt die zuletzt geänderte `.log`-Datei im konfigurierten Pfad.
3. Ereignisprotokoll in der Ereignisanzeige (`eventvwr.msc`) unter *Anwendungs- und Dienstprotokolle → Microsoft → Windows → DHCP-Server*; Name des Protokolls *nicht bestätigt*. Suche nach Warnungen zu Scope-Auslastung oder Autorisierung.
4. Kea: `sudo journalctl -u kea-dhcp4-server --since "1 hour ago"`. Die typischen Meldungsnamen aus dem Testlauf: `DHCP4_LEASE_ALLOC`, `DHCP4_LEASE_ADVERT`, `DHCP4_PACKET_NAK_0001`.
5. Notiere für Windows und Kea je drei Ereignisse, die du im Betrieb melden lassen würdest (Alarmkriterien).

### Teil 3: Sicherung und Wiederherstellung

*(Lerneinheit 10.3, Praxisaufgabe 3)*

**Windows-Export**

```powershell
.\10.1-export-sichern.ps1 -WhatIf
.\10.1-export-sichern.ps1
Get-ChildItem C:\DhcpSicherung
```

Das Skript ruft `Export-DhcpServer -File <Datei> -Leases` auf. Die Datei enthält Konfiguration und Leases.

**Kea**

```bash
sudo ./10.1-kea-sichern.sh
```

Das Skript legt ein Archiv mit Konfiguration und Lease-Datei an und listet seinen Inhalt. Es lief im Test (Dateien aus `/etc/kea/`).

**Wiederherstellung (Windows):** Auf `SRV-WIN-DHCP1` einen Scope löschen und aus dem Export zurückholen:

```powershell
Remove-DhcpServerv4Scope -ScopeId 192.168.20.0 -Force
Import-DhcpServer -File C:\DhcpSicherung\dhcp-export-<Zeitstempel>.xml -BackupPath C:\DhcpSicherung\vorher\ -ScopeId 192.168.20.0 -Leases
Get-DhcpServerv4Scope
```

`-BackupPath` ist laut Dokumentation Pflicht (Position 1) und nimmt eine Sicherung des Zustands vor dem Import auf. Existiert der Scope noch, wird er nur mit `-ScopeOverwrite` ersetzt, sonst erscheint eine Warnung. **Mache vorher einen Checkpoint.**

**Wiederherstellung (Kea):** Archiv entpacken, Dienst anhalten, Dateien zurückkopieren, Rechte setzen (`root:_kea`, `640`), `kea-dhcp4 -t`, Dienst starten.

### Teil 4: Migration auf einen anderen Server

*(Lerneinheit 10.4, Praxisaufgabe 4)*

1. Auf `SRV-WIN-DHCP1`: Export mit Leases (Teil 3).
2. Datei auf `SRV-WIN-DHCP2` kopieren (SMB-Freigabe oder Hyper-V-Dateikopie).
3. Auf `SRV-WIN-DHCP2`: Rolle installieren, autorisieren, dann

```powershell
Import-DhcpServer -File C:\DhcpSicherung\dhcp-export-<Zeitstempel>.xml -BackupPath C:\DhcpSicherung\vorher\ -Leases
```

4. Prüfen: `Get-DhcpServerv4Scope`, `Get-DhcpServerv4Reservation -ScopeId 192.168.10.0`, `Get-DhcpServerv4OptionValue`.
5. Umschaltung: Auf `SRV-WIN-DHCP1` den Dienst anhalten (`Stop-Service DHCPServer`) und den Relay auf `RTR-LIN` auf `192.168.10.12` umstellen. Erst danach beim Client erneuern. Beachte: **Zwei aktive Server mit demselben Scope ohne Failover erzeugen Doppelvergaben.**
6. Notiere, welche Schritte nicht automatisch übernommen wurden (zum Beispiel Autorisierung, DNS-Dienstkonto, Failover-Beziehung).

### Teil 5: Betriebsdokumentation

*(Lerneinheit 10.5, Praxisaufgabe 5)*

Erstelle die Datei `dhcp-betriebsdokumentation.md` in deinem Laborordner mit diesen Abschnitten (Gerüst, kein Pflicht-Inhalt aus dem Rohmaterial):

| Abschnitt | Inhalt |
|---|---|
| Adressplan | Netze, Scopes, Bereiche, Ausschlüsse, Reservierungen |
| Optionen | Router, DNS, Domäne je Scope; Abweichungen auf Server-Ebene |
| Server | Namen, Adressen, Rollen, Versionen (`kea-dhcp4 -V`, Windows-Build) |
| Hochverfügbarkeit | Failover-Beziehung oder Split-Scope, Zuständigkeiten |
| Überwachung | Schwellen, Skripte, wer wird informiert |
| Sicherung | Was, wann, wohin, wie lange aufbewahrt |
| Wiederherstellung | Schrittfolge aus Teil 3 und 4 mit Zeitbedarf (RTO) |
| Änderungsprotokoll | Datum, Änderung, Person |

Kein Passwort, kein Geheimnis und keine echte Domäne in diese Datei schreiben.

## Hintergrund

### Warum Auslastung beobachten?

Ein erschöpfter Scope macht sich erst durch Beschwerden bemerkbar: neue Geräte bekommen keine Adresse. Die Auslastung ist ein Frühindikator. Für dynamische Umgebungen (Besucher, WLAN) ist 80 Prozent ein üblicher Startwert für eine Warnung; die richtige Schwelle hängt von der Lease-Dauer ab.

### Audit-Log

Das Audit-Log liegt als Textdatei vor und rotiert nach Wochentagen (*Muster nicht bestätigt*). Es zeigt, wer wann welche Adresse bekam, und ist deshalb auch eine Datenschutzfrage: Aufbewahrungsdauer festlegen und Zugriff beschränken.

### Sicherungsstrategie

Konfiguration ändert sich selten, Leases ständig. Für die Konfiguration genügt eine Sicherung nach jeder Änderung; Leases lassen sich notfalls neu verteilen. Auch ohne Lease-Sicherung kommen die Clients nach Ablauf der Lease wieder zu einer Adresse. Mit Failover (Modul 7) liegt ein Lease-Abbild ohnehin beim Partner, ersetzt aber keine Sicherung.

### Migration

Export und Import übertragen Konfiguration und optional Leases. Dinge außerhalb der Datei (Active-Directory-Autorisierung, DNS-Dienstkonto, Windows-Firewall-Regeln, Relay-Ziel) müssen separat behandelt werden.

## Hinweise

- Sicherungsdateien enthalten Netzstruktur und MAC-Adressen; schütze sie wie Konfigurationsdaten.
- Importiere nie ungeprüft eine Datei unbekannter Herkunft.
- Teste die Wiederherstellung wirklich; eine Sicherung ohne Wiederherstellungstest ist nur eine Hoffnung.

<summary>Musterlösung anzeigen</summary>

### Soll-Zustand

| Prüfung | Soll |
|---|---|
| Statistik | Spalten `ScopeId` und `PercentageInUse`; kleiner Pool überschreitet 80 Prozent |
| Audit-Log | Pfad aus den Einstellungen, Zeilen mit Vergaben |
| Export | XML-Datei im Ordner `C:\DhcpSicherung` |
| Kea-Archiv | `etc/kea/kea-dhcp4.conf` (und weitere vorhandene Dateien) im Archiv |
| Import | Scope `Netz-B` wieder vorhanden |
| Migration | Alle Scopes, Reservierungen und Optionen auf `SRV-WIN-DHCP2` |

### Antworten

1. Nur die Einstellungen (Pfad, Aktivierung, Größe). Der Inhalt steht in den Dateien im Pfad.
2. Eine niedrigere Schwelle (etwa 60–70 Prozent), weil bei kurzer Lease der Bedarf stark schwankt. Die Zahl ist eine Annahme, keine Vorgabe.
3. Enthalten: Konfiguration, optional Leases. Nicht enthalten: Autorisierung in AD, Dienstkonto, Firewall, Relay-Ziele.
4. Beide vergeben Adressen aus demselben Bereich und wissen nichts voneinander: Doppelvergabe, Adresskonflikte.
5. Siehe Frage 3.

</details>

## Aufräumen und Rückkehr zum Ausgangszustand

- Pool von `Netz-B` wieder auf `192.168.20.100–192.168.20.199` setzen (`Set-DhcpServerv4Scope -ScopeId 192.168.20.0 -StartRange 192.168.20.100 -EndRange 192.168.20.199`) und Test-Leases verfallen lassen oder löschen.
- `SRV-WIN-DHCP2`: Scopes entfernen oder Server herunterfahren; Relay-Ziel zurück auf `192.168.10.11`.
- Sicherungsordner behalten (Modul 12 verwendet ihn).
