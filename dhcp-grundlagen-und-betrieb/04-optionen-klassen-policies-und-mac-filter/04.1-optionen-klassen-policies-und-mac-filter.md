## Lernziele

Nach dieser Übung kannst du

- die Optionsebenen Server, Scope, Reservierung und Policy und ihren Vorrang erklären,
- Vendor- und User-Classes unterscheiden und eine User-Class auf einem Windows-Client setzen und serverseitig auswerten,
- eine Policy mit Bedingung und abweichenden Optionen oder Lease-Dauer konfigurieren,
- MAC-Filter (Allow- und Deny-Liste) konfigurieren, testen und ihre Grenzen benennen.

## Voraussetzungen

- Modul 3 abgeschlossen. Checkpoint `M4-Anfang` auf `SRV-WIN-DHCP1` (Teil 1).
- Ausgangszustand: `CLI-WIN-A` hat `192.168.10.150` per Reservierung.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **Vendor-Class** | Vom Hersteller des Clients gesetzte Kennung (Option 60), z. B. für Gerätetypen. |
| **User-Class** | Vom Administrator frei vergebene Kennung (Option 77), im Client eingetragen. |
| **Policy** | Regel mit Bedingungen (z. B. User-Class, MAC-Präfix), die Optionen oder Lease-Dauer überschreibt. |
| **MAC-Filter** | Allow-Liste (nur diese MACs bekommen Adressen) oder Deny-Liste (diese MACs nicht). |
| **Option 42, 66, 67** | Zeitserver (NTP), Boot-Server und Boot-Dateiname. |

## Aufgabe

### Teil 1: Zusätzliche Optionen

*(Lerneinheit 4.1, Praxisaufgabe 1)*

**1. Checkpoint**

```powershell
Checkpoint-VM -Name SRV-WIN-DHCP1 -SnapshotName M4-Anfang    # Hyper-V-Host
```

**2. Option 42 (Zeitserver) setzen**

- **GUI:** Scope `Netz-A` → *Bereichsoptionen* → Rechtsklick → *Optionen konfigurieren* → Option 042 *NTP-Server* → `192.168.10.1`.
- **PowerShell:**

```powershell
Set-DhcpServerv4OptionValue -ScopeId 192.168.10.0 -OptionId 42 -Value 192.168.10.1
Get-DhcpServerv4OptionValue -ScopeId 192.168.10.0
```

**3. Im Mitschnitt nachweisen** (`RTR-LIN`: `sudo ./01.1-mitschnitt.sh net-a`; `CLI-WIN-A`: `ipconfig /renew`)

Suche im ACK (und im OFFER) die Zeile `NTP (42)` mit `192.168.10.1`. Ob `CLI-WIN-A` die Option **auswertet**, ist *nicht bestätigt*. Verlangt wird nur der Nachweis, dass der Server sie sendet. Beachte: Der Server sendet laut Standard nur Optionen, die der Client angefordert hat (Parameter Request List). Fordert der Client Option 42 nicht an, fehlt sie im Mitschnitt (*nicht bestätigt* für Windows).

**4. Weitere Optionen im Überblick** (ohne Umsetzung)

Notiere aus Lerneinheit 4.1: Option 119 (Domänen-Suchliste, RFC 3397), Option 121 (klassenlose statische Routen, RFC 3442), Optionen 66/67 (Boot-Server und -Datei). Welche davon brauchen eine Gegenstelle auf dem Client? Die Unterstützung je Server und Client ist *nicht bestätigt*.

### Teil 2: User-Class und Policy

*(Lerneinheiten 4.2 und 4.3, Praxisaufgabe 2)*

**1. Reservierung vorübergehend entfernen**

```powershell
Remove-DhcpServerv4Reservation -ScopeId 192.168.10.0 -IPAddress 192.168.10.150
```

Auf `CLI-WIN-A`: `ipconfig /release`. Grund: Die Wirkung von Policy-Leasedauer auf Reservierungen ist nicht bestätigt; ohne Reservierung ist das Ergebnis eindeutig. **Rückbau am Ende von Teil 3.**

**2. User-Class auf dem Server anlegen**

- **GUI:** `dhcpmgmt.msc` → *IPv4* → Rechtsklick → *Benutzerklassen definieren* → *Hinzufügen*: Name `Labor`, ASCII-Eintrag `Labor`.
- **PowerShell:**

```powershell
Add-DhcpServerv4Class -Name 'Labor' -Type User -Data 'Labor' -Description 'Laborrechner Modul 4'
Get-DhcpServerv4Class
```

**3. Class-ID auf dem Client setzen** (`CLI-WIN-A`)

```powershell
ipconfig /setclassid "Ethernet" Labor
ipconfig /showclassid "Ethernet"
```

Der Adaptername steht in Anführungszeichen und kann abweichen (`Get-NetAdapter`). Der Befehl stammt aus dem Lehrplan und ist *nicht bestätigt*; `ipconfig /?` zeigt die Optionen.

**4. Policy anlegen**

- **GUI:** Scope `Netz-A` → *Richtlinien* → *Neue Richtlinie*: Name `Labor-Clients`, Bedingung *Benutzerklasse gleich Labor*, Lease-Dauer 1 Stunde, Option 15 abweichend setzen.
- **PowerShell:**

```powershell
Add-DhcpServerv4Policy -Name 'Labor-Clients' -ScopeId 192.168.10.0 -Condition OR `
    -UserClass EQ,Labor -LeaseDuration (New-TimeSpan -Hours 1)
Set-DhcpServerv4OptionValue -ScopeId 192.168.10.0 -PolicyName 'Labor-Clients' -DnsDomain labor.corp.example.com
Get-DhcpServerv4Policy -ScopeId 192.168.10.0
```

Die Syntax `-UserClass EQ,Labor` entspricht den Beispielen in der Dokumentation (`-VendorClass EQ,Android`). Achtung bei `-LeaseDuration`: Eine nackte Zahl wird als **Tage** gelesen (die Dokumentation zeigt `-LeaseDuration 10` für 10 Tage). Gib deshalb immer eine `TimeSpan` an.

**5. Wirkung nachweisen**

```powershell
ipconfig /renew
ipconfig /all
Get-DhcpServerv4Lease -ScopeId 192.168.10.0
```

Erwartet (*nicht bestätigt*): Lease-Dauer 1 Stunde statt 8, DNS-Suffix `labor.corp.example.com` statt `corp.example.com`. Weise es an zwei Stellen nach: im Lease-Eintrag (Ablaufzeit) und im Mitschnitt (Option 51 Lease-Time `3600`, Option 15).

### Teil 3: MAC-Filter

*(Lerneinheit 4.4, Praxisaufgabe 3)*

**1. Deny-Eintrag anlegen**

- **GUI:** `dhcpmgmt.msc` → *IPv4* → *Filter* → *Verweigern* → Rechtsklick → *Neuer Filter*: MAC-Adresse von `CLI-WIN-A`; Filter anschließend im Kontextmenü von *Filter* → *Eigenschaften* → Reiter *Erweitert* aktivieren.
- **PowerShell:**

```powershell
Add-DhcpServerv4Filter -List Deny -MacAddress 00-15-5D-xx-xx-xx -Description 'Test Modul 4'
Set-DhcpServerv4FilterList -Deny $true
Get-DhcpServerv4FilterList
Get-DhcpServerv4Filter
```

`Set-DhcpServerv4FilterList` (Parameter `-Allow`, `-Deny`, jeweils `Boolean`) ist gegen Microsoft Learn geprüft; Syntax und MAC-Schreibweise von `Add-DhcpServerv4Filter` sind *nicht bestätigt*. Setze deine MAC-Adresse ein.

**2. Auswirkung testen**

```powershell
ipconfig /release
ipconfig /renew
```

Im Mitschnitt: DISCOVER des Clients ohne OFFER. Erwartet (*nicht bestätigt*): Der Server bleibt stumm; der Client wiederholt, bis er aufgibt (Link-Local-Adresse, Modul 1). Der Server protokolliert die Ablehnung im Audit-Log (Modul 10).

**3. Rückbau (Pflicht)**

```powershell
.\04.1-rueckbau.ps1 -ClientId 00-15-5D-xx-xx-xx -WhatIf   # dann ohne -WhatIf
```

Das Skript führt aus: Filter entfernen, Deny-Liste deaktivieren, Policy `Labor-Clients` entfernen, Class `Labor` entfernen, Reservierung `.150` wiederherstellen. Auf `CLI-WIN-A`: `ipconfig /setclassid "Ethernet"` (leert die Class-ID), `ipconfig /renew`. Prüfe: `.150`, Router, DNS und Domäne wie in Modul 3.

## Hintergrund

### Optionsebenen und Vorrang

Der Server wertet Optionen von allgemein nach speziell aus: Server, Scope, dann Policy, dann Reservierung; spezifischere Ebenen überschreiben allgemeinere. Die genaue Reihenfolge zwischen Policy und Reservierung ist *nicht bestätigt*. Prüfe sie, wenn du beides auf dasselbe Gerät legst, mit `Get-DhcpServerv4OptionValue -ScopeId … -ReservedIP …` und im Mitschnitt.

### Classes und Policies

Eine **Vendor-Class** beschreibt, was der Client *ist* (der Hersteller trägt sie ein), eine **User-Class** beschreibt, was der Administrator ihm *zuordnet*. Policies verbinden Bedingungen (Class, MAC-Präfix, Relay-Information, Name) mit abweichenden Werten. Typischer Einsatz: IP-Telefone bekommen andere Optionen als PCs, Laborrechner kürzere Leases.

### Grenzen des MAC-Filters

MAC-Adressen sind unverschlüsselt im Netz sichtbar und leicht fälschbar. Ein Filter hält versehentliche Fremdgeräte fern, schützt aber nicht vor einem Angreifer im selben Segment. Er ersetzt weder Portsicherheit noch 802.1X (Modul 11).

## Hinweise

- Policy-Verarbeitung ist standardmäßig aktiv; ob `-ActivatePolicies` im Labor ausgeschaltet ist, siehst du mit `Get-DhcpServerSetting`.
- Die Deny-Liste wirkt serverweit, nicht nur im Scope. Wer vergisst sie zurückzunehmen, sperrt `CLI-WIN-A` in allen späteren Modulen aus.
- Setze `ipconfig /setclassid` nur auf dem Testclient.

## Prüfbefehle und Kontrollfragen

Zustand am Ende von Modul 04:

```powershell
Get-DhcpServerv4FilterList                       # Allow und Deny: False
Get-DhcpServerv4Filter                           # leer
Get-DhcpServerv4Policy -ScopeId 192.168.10.0     # keine Policy "Labor-Clients"
Get-DhcpServerv4Class                            # ohne "Labor"
Get-DhcpServerv4Reservation -ScopeId 192.168.10.0   # .150
Get-DhcpServerv4OptionValue -ScopeId 192.168.10.0   # 3, 6, 15, 42
```

**Kontrollfragen**

1. In welcher Reihenfolge werden Optionen aus Server, Scope, Reservierung und Policy angewendet, und welcher Wert gewinnt?
2. Was unterscheidet eine Vendor-Class von einer User-Class?
3. Warum ist ein MAC-Filter kein wirksamer Schutz gegen einen böswilligen Teilnehmer im Netz?
4. Welche Bedingungen kann eine Policy auswerten, und was ist ein sinnvoller Einsatzfall?

### Antworten auf die Kontrollfragen

1. Von allgemein nach speziell; die spezifischere Ebene gewinnt: Server < Scope < Policy/Reservierung. Wie Policy und Reservierung zueinander stehen, ist *nicht bestätigt*.
2. Die Vendor-Class stammt vom Hersteller des Geräts (Option 60), die User-Class vom Administrator (Option 77).
3. MAC-Adressen sind nicht geheim und lassen sich ändern; wer im Segment sitzt, kann eine erlaubte MAC nachahmen.
4. Zum Beispiel User-Class, Vendor-Class, MAC-Präfix, Relay-Information, Name. Einsatzfall: Telefone, Drucker, Laborgeräte mit eigenen Optionen oder Lease-Zeiten.
